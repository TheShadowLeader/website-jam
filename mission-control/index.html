04 · Build out

Add a page or section.

/website-jam · BROWSE+ADD

Mid-build workhorse. Name the section; you get 2–3 patterns that fit the conversion skeleton, you pick, it gets built with real copy. Repeat until the site is whole.

05 · Verify

QA gate.

unskippable

Every CSS/visual change passes through real browser screenshots — rest, hover, mobile — saved to qa/<today>/, plus a design audit. No screenshots, no "done". This is what keeps builds honest.

runs automatically on any "this is finished" claim — this forces it on demand
06 · Handoff

Handoff.

/website-jam · HANDOFF

The PR gets drafted or updated — summary, test plan, QA screenshots, preview link slot. The client and reviewer never get pinged automatically; you decide when and how the link goes out. Production deploys for client work stay yours too.

07 · Close out

Postmortem.

memory + promotion

After ship: project memory gets updated, and any pattern used on 3+ projects gets promoted into your own kit as an owned primitive — the system compounds with every build.
